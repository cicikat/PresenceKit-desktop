# 分阶段启动：加载页 → 完整窗口 → 后端数据（2026-11-27）

状态：planned，先写工单后施工；完成后 push 并合并 main。

## 用户目标与顺序

1. 命令行完成必要初始化后打开主窗口，立即显示完整、安静的加载页，不出现绿色栏加空白底壳。
2. 前端代码、本机偏好和本机登录配置检查并行。前端准备好后完整呈现窗口，不等待后端联网成功。
3. 后端连接尽早在后台进行；连接中、断开与重连由既有连接反馈和设置入口处理。数据就绪后原位补入历史、角色等，不清空草稿、不重建窗口。
4. 本机未配置或登录检查失败仍走原有引导和重试；不能为首屏速度绕过鉴权、Session 或文件偏好。

## 施工范围与依赖

- 先检查入口、原生窗口显示时机、登录门禁与聊天连接链路，确认哪些是本机检查、哪些等待真实后端。
- 用完整加载页替换 HTML 底壳，并让 React 接管前后沿用相同呈现。文案来自语义 i18n key，中英文一致；辅助透明窗口保持透明，不显示主窗加载页。
- 明确前端就绪与连接就绪的边界，必要时仅调整阻塞前端的等待。保留连接、失败、重试、设置与已有业务入口。
- 不新增后端契约或设置，不修改后端/手机代码；若发现跨端实际影响，执行三面检查并记录。
- 更新架构、前端结构、已知问题与本工单；静态检查、隔离浏览器的慢代码/慢本机配置/慢后端/断线恢复与草稿历史回归完成后交付。

## 验收

- JavaScript 尚未完成加载时，主窗口已有明确加载反馈，DOM/CSS 无绿栏空白底壳。
- 前端就绪后加载页退出；后端一直挂起或离线时仍可操作完整窗口与连接设置。
- 后端数据迟到只更新内容，不重复历史，不丢草稿；未配置鉴权不发业务请求。
- 加载页中英文、减少动态效果和辅助窗口隔离通过浏览器检查。
- 原生安装版冷启动与物理网络验收未完成时明确保留 open；200ms 不通过最低展示时长或掩盖网络故障伪造。
