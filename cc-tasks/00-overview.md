## 回答茶茶的两个问题

### Q1 配色自定义做在前端还是管理面板？→ 前端，单开一页
- 配色是**用户日常的个性化偏好**、要即时预览生效，属于前端偏好区，不该塞进管理面板（管理面板更适合部署/多用户治理类配置）。
- "前端导出配色觉得怪"——其实不怪：导出 = 把你的配色**按主题清单格式(`theme.json`)导出**，这正好就是 mod 系统吃的格式（见 Q2）。所以"导出配色"≈"导出成一个轻量 mod"，是同一种货币，不别扭。
- 塞进"外观"页会臃肿 → **新开一页"色彩自定义"**（偏好顶栏加一个 tab），chat 和 dream 各自一页。

### Q2 直接调色 vs mod 改，区别在哪？→ 同一套底座的两层
本仓 mod 系统已经存在（`docs/theme-mod-system-spec*.md`，v1 已落地）：一个主题/mod = 磁盘 `public/themes/<id>/theme.json`（一组 CSS 变量 token 值）+ 可选 `theme.css`（带安全检测的任意 CSS，能改布局/结构/圆角）+ 资源。
- **直接调色（基础设置）** = 在 app 里用 GUI 编辑那组 **token 值**（颜色/字体色/字号），不写文件、不写 CSS。范围被锁在 app 暴露的变量槽内，安全、有界。
- **mod（插件）** = 整包磁盘主题，除了 token 还能带 `theme.css` 改**布局/间距/圆角/显隐**等——更强但更危险、可能随版本失效。
- 关系：配色预设 = mod 能力的**受控子集（只 token 那部分）**。所以：**颜色/字体 = 基础设置；动布局 = mod territory**。配色编辑器产出的预设，数据形状和 mod 的 `theme.json` 一致，"导出"就是落成一个最小 mod。
