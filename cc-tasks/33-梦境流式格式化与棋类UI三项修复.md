## 任务 A：梦境流式输出边流边格式化（消灭"先一坨、结束后再美化"）

### 现象
梦境对话自从接了伪流式后：流式期间是一整坨无格式纯文本，HTTP 响应返回后才整体替换为分段美化样式（say/do/env/feel 气泡）。观感是"打完一大段突然变身"。

### 根因（已定位，不是两通道打架）
`src/windows/dream/hooks/useDreamChat.ts`：

- 流式期间（`armHttpPseudoStream` 回调）只往消息里写 `text`（纯文本），**没有 segments** → `DreamChatPanel.tsx` L136 判断 `msg.segments?.length` 为空，走纯文本渲染分支。
- `dreamChat()` HTTP 响应回来后才 patch 上 `segments` / `segmentedContent`（后端 `dream_turn` 解析好的）→ 渲染整体切换到 `DreamSegmentedReply`。

即：分段信息只在终态存在，流式态天然没有。两条通道协作本身是正常的（WS 伪流式先播、HTTP 终态对账），缺的是**流式态的增量解析**。

### 修复要求
1. 新建客户端增量叙事解析器 `src/shared/api/incrementalNarrativeParser.ts`，语法与后端 `Emerald-presence/core/narrative_parser.py` 对齐：
   - XML 格式：`<say>…</say>`、`<do>`、`<env>`、`<feel>`（检测到任一已知开标签即走 XML 路径）；
   - Markdown 格式：整行 `*…*`→do、整行 `_…_`→feel、`> …`→env、其余→say；
   - **开区间语义**：遇到开标签/起始符即开启一个新 segment 并把后续增量字符流入该 segment；遇到对应闭合符（闭标签 / 同符号再现 / 换行终止行级规则）即收口，回到默认态等待下一个。未闭合的尾部段按当前已开类型渲染（乐观渲染），终态对账时校正。
   - 接口建议：纯函数 `parseIncremental(fullText: string): NarrativeSegment[]`——每次 delta 后用累计全文重算（回复量级小，无需真正的流式状态机；重算实现最简单、且和后端终态解析行为最容易对齐）。
2. `useDreamChat.ts` 流式回调里：每次 delta 后 `segments = parseIncremental(normalized)` 一并写入消息对象 → `DreamChatPanel` 现有的 `DreamSegmentedReply` 分支自动生效，流式期间即分段渲染。
3. HTTP 终态返回后仍以后端 `resp.segments` 覆盖（现逻辑保留），保证最终一致；覆盖时避免视觉跳变（多数情况下两者应一致）。
4. 加单测（vitest，参考 `activity-api.test.ts` 的组织方式）：混排文本逐字符喂入，断言中间态 segment 类型序列合理、终态与整段解析一致；覆盖未闭合标签的乐观渲染 case。

### 验收
- 流式期间：`*动作*`、`> 环境`、对白实时以各自样式渐进出现，无"结束后整体变身"。
- 中断/错误路径（现有 filter/替换逻辑）不回归。

## 任务 C：棋类旁"和xx说说"聊天面板内部可滚动

### 现象
聊天消息多了以后面板无限变高，只能整页（连棋盘一起）滚动；期望消息列表在面板内自行滚动。

### 根因（已定位）
`ActivityCompanionPanel.tsx` L237-242：面板 `minHeight: 360` 但**无高度上限**；`CompanionSidebar.tsx` 外层容器也无高度约束，且 ChessPage 的 board row 是 `alignItems: 'flex-start'` → 面板随内容撑高，内部 `flex:1, overflowY:auto` 的消息区永远撑不到滚动条件。

### 修复要求
1. 给 `CompanionSidebar` 容器加视口约束 + 吸附：`position: sticky; top: <ribbon 高度+间距>; maxHeight: calc(100vh - <顶部占用>)`（具体扣除值以 ActivityWindow 实际布局为准，`display:flex; flexDirection:column` 已有）。
2. `ActivityCompanionPanel` 根节点加 `maxHeight: 100%` / `minHeight: 0`，确保内层消息区 `overflowY: auto` 生效；自动滚底逻辑（L161 `scrollTop = scrollHeight`）保留并确认仍工作。
3. Chess 与 Gomoku 两页都验证（共用 CompanionSidebar，理论上一处改动两处生效）；Reading 页若也用该面板一并回归。

### 验收
- 对局中连续聊 20+ 条：面板高度不超过视口，消息区内部出现滚动条，新消息自动滚到底；整页滚动时面板吸附在视口内。
