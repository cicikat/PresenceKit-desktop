# Brief 34 · 首启 token 引导 + 401/429 人话化 + dream 状态准确显示

> 背景:异机真机实测(20260718),新用户装好前后端后,前端直接裸报 429/401,
> 无任何指引;dream 期间统一显示「角色正在做梦因此无法聊天」有误导性。
> 前置依赖:后端仓 Brief 93(密钥本按钮/401 hint)与 Brief 94 §2(dream 状态
> 字段)。§1/§2 可先按契约实现,联调等后端落地;§4 无依赖可先做。

## 1. 🟡 无 token 首启引导

- 启动时检测 token 未配置 → 不进聊天界面,显示引导页/弹窗:
  「到后端管理面板右下角『打开密钥本』,复制名为 `<token条目名>` 的密钥,
  粘贴到下方输入框」——条目名与后端 `secrets.local.yaml` 实际写入的 key
  名称严格一致(联调时核对),并附管理面板地址(用户已配置的后端地址推导)。
- 输入框直接在引导页内,粘贴→校验(调一次鉴权接口)→成功进入聊天;
  失败显示后端 401 hint(见 §2)。
- 文案走 `src/shared/i18n/` 语义 key,禁止硬编码中文(仓库规则 7)。

## 2. 🟡 401 / 429 错误人话化

- 401:透传后端响应体 `hint` 字段(Brief 93 §6),并附「重新填写密钥」按钮
  跳 §1 引导页;无 hint 字段(旧后端)时用本地兜底文案。
- 429:显示「后端限流/上游模型繁忙,稍后自动重试」,带退避自动重试,
  不再把裸状态码抛给用户。
- 其他 5xx/网络错误顺手统一走同一错误展示组件(区分:后端没启动 / 地址错 /
  后端异常三种文案)。

## 3. 🟡 dream 状态准确显示

- 接 Brief 94 §2 的结构化字段(`dream_state` / `expected_end` / `blocks_chat`):
  - `blocks_chat=false`:不再禁聊,提示「正在做梦,回复会延迟到梦醒」。
  - `blocks_chat=true`:显示状态 + 预计结束时间(有 `expected_end` 时);
    无法预估则显示开始时间「做梦中,自 xx:xx」。
  - 状态异常(时长远超正常):提示「梦境状态异常,可尝试重启后端」。
- 旧后端无这些字段时降级回现有文案,不崩。

## 验收

- 全新安装、未配 token:启动进引导页而非报错;粘贴正确 token 后直达聊天;
  错误 token 显示人话提示。
- 断开后端/填错地址/后端 500 三种场景文案各自正确;429 自动重试可观测。
