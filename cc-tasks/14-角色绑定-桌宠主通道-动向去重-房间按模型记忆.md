## A. 角色绑定层（问题 1）

新建 `src/shared/characterBindings.ts`（走 uiPreferences，key `character.bindings`）：

```ts
Record<charId, {
  petVisualStyle?: PetVisualStyle;
  live2dModelDir?: string;
  roomCharacterFile?: string;
  roomSceneFile?: string;
}>
```

- **捕获**：角色 X 为 active 时，用户改桌宠风格 / Live2D 模型 / 房间模型 → 同步写 `bindings[X]`（在 ChatWindow 的 `onPetVisualStyleChange` 等回调处、CallSettingsPage 模型切换处挂钩）。
- **应用**：`onCharacterSwitched`（`ChatWindow.tsx:1549`）→ 若 `bindings[新char]` 有值，依次 `savePetVisualStyle` / `saveLive2DSettings` / `saveRoomSettings` 应用；**无值则什么都不做**——现有全局值就是 legacy 兜底（用户确认：不需要兜底到额外文件）。
- **立即刷新状态**：切换后立刻调 `retryMood()` / `retryActivity()`（`useBackendStatePolling` 已返回），不等下一个 30-60s 轮询。
- **activeCharId 进 StateEngine**：`store.ts` 增加 `activeCharId` 字段，ChatWindow 拉到 prompt-assets 后写入——§B 时间轴和桌宠窗都要用。
- 桌宠窗跟随：桌宠窗已订阅 `subscribeRoomSettings` / `subscribePetVisualStyle` 的 storage 事件……**注意**：跨窗 storage 事件在 WebView2 下不可靠（§D 同款问题），绑定应用后通过 pet bridge 广播一条 snapshot/prefs 事件强制桌宠窗重载（复用 §D 的通道）。

验收：yexuan ↔ 另一角色来回切，桌宠模型、视频通话模型、mood、动向全部各归各；从未绑定过的角色保持切换前的全局配置。

## D. 桌宠话语主通道化（问题 4）

### D.0 现状回答（用户问「是 legacy 还是哪条通道」）

都不是——桌宠气泡是 **ChatPanel 的转发**：`scheduleAssistantSegments`（`ChatPanel.tsx:927`）把回复经 `summarizePetReply` 截成第一句（≤92 字）后走 Tauri 事件发给 pet 窗。因此：主窗口 ChatPanel 的去重守卫、梦境隐藏、fallback 竞态任何一环吞掉渲染，桌宠与聊天框就两头不同步（「我回来了」正是调度器主动消息走了其中一条被吞路径）。

### D.1 关键约束

后端 WS 是**单连接**（`desktop_ws.py handle_connection`：新连接顶替旧连接），桌宠窗**不能**自己 `wsClient.connect()`，否则会把主窗口踢下线。Rust 侧 `ws_bridge.rs` 的 `app_handle.emit` 本就广播到所有窗口，但 `WSClient` 按 `connectionId` 过滤，桌宠窗拿不到主窗口的 id——所以走**主窗口转发**方案。

### D.2 方案

1. **转发层**：在主窗口 shell 层（`main.tsx` 或 ChatWindow 顶层，**不在 ChatPanel 内**，不经其去重/梦境门控）订阅 `wsClient` 的 `channel_message` / `message_segments` / `message_stream_start|delta|end`，原样 `emitTo('pet', 'pet://turn', payload)`。**不再 summarize，转发全文。**
2. **桌宠接收**：PetWindow 监听 `pet://turn` 渲染气泡。最简实现：只消费 `channel_message`（canonical 全文），按 `splitReply`（`\n+` 分段）逐段或整段展示，展示时长随文本长度（如 `max(6s, len*80ms)`）。流式 reveal 想做再复用 `windows/room/turnIngest.ts`（它就是干这个的），第一版不强求。
3. **输入框**：pet 窗底部加输入框（样式参照 `RoomWindow.tsx:236-270` 的 chat input bar；默认半透明、hover/focus 提升），回车 `sendChat()`（HTTP 走 Tauri command，任意窗口可用——pet 语音热键已在用）。回复经 WS → 主窗转发 → 气泡；同轮也会自然出现在主聊天历史（同一后端通道，天然一致）。
4. **清理**：移除 `snapshot.latestAssistantText` 渲染路径（`PetWindow.tsx:83-88, 149-170`）；`Model3DStage.onNewSpeech`（`Model3DStage.tsx:42-47`）改由 `pet://turn` 驱动；`summarizePetReply` 与 ChatPanel 内的 `publishPetSnapshot({latestAssistantText})` 删除。`thinking` 状态保留现有 snapshot 通道。
5. 边界：主窗口关闭则桌宠也收不到（pet 由主窗口 spawn，可接受，注释说明即可）。

验收：聊天窗发消息 → 桌宠同步弹全文气泡；桌宠输入 → 主聊天历史出现该轮对话；调度器主动消息两端同时出现；梦境模式下行为与 RoomWindow 一致。

## E. 桌宠缩放：实时生效 + 头部锚定（问题 4-缩放）

1. **实时**：不再依赖 `onUIPrefChange`（同窗事件，跨窗失效；WebView2 的跨窗 storage 事件也不可靠）。ChatWindow 滑杆变化时除 `setUIPref` 持久化外，经 pet bridge 发 `pet://prefs` 事件（`emitTo`，载荷 `{ model3dZoom?, live2dZoom? }`），`Model3DStage` / `Live2DStage` 监听后 setState。localStorage 仍是重启后的真值来源。
2. **锚点（拍板：顶部/头部锚定）**：缩放时保持模型包围盒顶端（头顶）在视口中的投影位置不变（约距顶 12-15%），放大时向下方/身体裁切，头永不出框。
   - `Model3DStage`：模型加载完成后算 `THREE.Box3` 得 `headY = bbox.max.y`；zoom 变化时按 `headY` 反解 `camera.position.y`（正交相机，视口半高 = `FRUSTUM_HH / zoom`，令 `headY` 映射到视口顶部下方 15% 处），`updateProjectionMatrix()`。
   - `Live2DStage`：同理，zoom 变化时联动 y offset 保持模型顶端固定（Live2D 侧用现有 offset 机制换算）。
   - 验收：全身模型 zoom 1→4 连续拖动，头顶始终可见且屏幕位置基本不动；缩小回 1 复原。

## F. 房间按「场景×模型」记忆视角/站位 +「保存预设」定位（问题 5）

已有先例可抄：`perCharacter`（boneMap/physicsBones 按 characterFile 隔离 + legacy 一次性迁移，`roomSettings.ts:59-76, 207-260`）；命名预设 `roomPresets.ts`（整 blob 快照）已存在。

1. `RoomSettings` 新增：

```ts
perPlacement?: Record<string /* `${sceneFile}|${characterFile}` */, PlacementCfg>;
// PlacementCfg = { framing, fovDeg, scaleMul, offset, yawDeg, customView, anchorMode, props, idleClip? }
```

   站位/机位与场景强相关，所以 key 用 **场景×模型** 复合键（用户「场景也需要加入」的拍板）。灯光暂不入内（跨场景通用），后续有需要再扩。

2. **切换时机**（CallSettingsPage / useRoomScene 中 `characterFile` 或 `sceneFile` 的写点）：先把当前顶层 placement 字段快照进 `perPlacement[旧key]`，再应用 `perPlacement[新key]`；新 key 无记录则**保留当前顶层值不动**（= legacy 兜底，行为与现在一致）。
3. **单一真值**：顶层字段仍是「当前生效值」（「保存当前视角」「摆放」继续写顶层），顶层 placement 字段每次变化时同步回写 `perPlacement[当前key]`。
4. `validate()` 补 `perPlacement` 的 schema 校验（逐字段沿用现有 validate 函数，坏数据丢弃该 key）。
5. 命名预设 `roomPresets` 保留为跨组合手动快照；CallSettingsPage 文案区分「自动记忆（每个场景×模型独立）」与「手动预设」。

验收：模型 A 调好机位站位 → 切模型 B 调另一套 → 切回 A 完整复原；换场景后同一模型各有一套；从未调过的组合表现与现状一致。
