## A. 偏好不持久（根因已确认，优先级最高）

### A.1 根因

commit `67d9a98`（opensource rename）把 `tauri.conf.json` 的 `identifier` 从
`com.emerald-client.app` 改成了 `com.presencekit.desktop`。Windows 上 WebView2 的
user-data 目录按 identifier 派生——改名后 webview 换到了一个**全新的空 profile**，
所有 localStorage（全部 `emerald.ui.*`：字体大小、主题、颜色预设、房间设置、角色绑定、
动向时间轴……）一次性归零。旧数据还躺在旧 identifier 目录的 LevelDB 里，无实用导入手段，
按丢失处理。这也解释了「不确定还有没有别的变回默认」——是**全部**。

### A.2 修复：uiPreferences 改为文件后端（防再次发生）

localStorage 与 app 身份绑定太脆，偏好应落到受我们控制的文件：

1. **Rust**（`src-tauri/src/lib.rs`，紧挨 `client_config.rs` 的目录解析逻辑）：
   - `load_ui_prefs() -> String`：读 app config 目录下 `ui-preferences.json`，不存在返回 `"{}"`。
   - `save_ui_prefs(contents: String)`：原子写（临时文件 + rename）。
2. **TS**（`src/shared/uiPreferences.ts`）：
   - 新增 `initUIPrefs(): Promise<void>`——启动时（`main.tsx` 渲染前 await，pet/其他窗口入口同样）invoke `load_ui_prefs`，解析进内存 Map，并镜像写回 localStorage（保持现有跨窗 storage 事件同步机制不变）。
   - `getUIPref` 改为读内存 Map（同步，签名不变）；`setUIPref` 写内存 + localStorage 镜像 + **300ms debounce** invoke `save_ui_prefs`（全量序列化）。
   - 非 Tauri 环境（`npm run dev` 纯浏览器）fallback 纯 localStorage。
3. **迁移**：`load_ui_prefs` 返回空且 localStorage 存在 `emerald.ui.*` 键 → 用它们 seed 文件（把这次事故里"改动后新写入"的数据救回来）。
4. **顺手统一**：绕过 uiPreferences 直接用 localStorage 的模块改走 `getUIPref/setUIPref`：
   `petVisualStyle.ts`、`pet/mouseSettings.ts`、`petRoamSettings.ts`、`petRippleSettings.ts`、
   `SubFlow.tsx` 的时间轴（`subflow_timeline.*`）。各自 key 不变，读不到时从旧裸 key 迁移一次。

验收：改字体大小/主题/桌宠风格 → 完全退出重启 → 全部保留；删掉 `ui-preferences.json` 再启动 → 回默认不崩；双窗口（chat+pet）同时改偏好不互相覆盖（debounce 后以最后写入为准）。

## B. 自定义 UI 颜色预设无法二次编辑

位置：`ChatColorPage.tsx` + `theme/userPresets.ts` + `theme/registry.ts`。三个叠加问题，全修：

1. **编辑内容被外部刷新清空**：tokens 加载 effect 依赖 `[selectedPreset]`（对象引用）。
   `subscribeTheme(() => setPresets(loadUserPresets()))` 在任何主题事件（`setSlotTheme`、别的窗口 storage 事件触发 `applyByMode`、日夜自动切换定时器）时重建 presets 数组 → `selectedPreset` 引用变化 → effect 重跑 → `setTokens(已保存值)` + `setDirty(false)`，用户正在改的颜色被静默回滚。
   **修**：effect 依赖改为 `[selectedId]`；`dirty` 时跳过外部触发的 token 重载。
2. **预设在另一槽位下不可见**：`filteredPresets` 按 `base === (editSlot==='day'?'light':'dark')` 过滤。白天建的预设，晚上打开面板（editSlot 初值=当前激活槽）下拉框里就没有 → 表现为"保存过的预设找不到/改不了"。
   **修**：下拉框显示全部预设并带 `[日]/[夜]` 标记；选中与当前槽 base 不符的预设时自动切 editSlot。
3. **情绪反应色干扰编辑**：`moodReactive.applyMoodOverlay`（`ChatWindow.tsx:1276`，engine 每次状态更新触发）会内联覆写 `--accent`/`--forest` 等——正是编辑器里的 token，用户刚选的颜色几秒后被盖掉，像"没改成"。
   **修**：ChatColorPage 挂载时 `clearMoodOverlay()` 并挂起 overlay（加一个模块级 suspend 标志），卸载时恢复。
   顺带记录 known-issue：`computeMoodOverrides` 从**已被覆写的当前值**读色再偏移，连续叠加会漂移，建议以主题原始 token 为基准计算（可在本 PR 修或记 `docs/known-issues.md`）。

注意：§A 的存储丢失也会表现为"预设改了没存住"，先落 §A 再验收本节。
验收：新建预设 → 保存 → 关面板重开 → 再改 → 保存 → 重启，两轮修改都在；编辑过程中放置 2 分钟（跨 mood 轮询）颜色不回跳。

## D. 梦境面板白天模式聊天区灰底

目标状态（验收标准）：日间模式下聊天区底层是**白色**，四角有花卉色边缘染色（`.dream-theme__canvas` 的 radial 花彩 + 白雾），无灰色感。

排查顺序（按可能性）：

1. **持久化的日间色彩覆盖**：`DreamWindow.tsx:284` 把 `appearance.colorOverridesDay` 直接铺成内联 CSS 变量。检查 `emerald.ui.dream.appearance` 里 `colorOverridesDay` 是否残留灰值（尤其 `--dt-bg-1/2/3`）。若是：本次事故性数据直接清；并在 `dreamAppearance.ts` 的 load 校验里丢弃与 `DREAM_DAY_DEFAULTS` 键集不符的 key。
2. **日间自定义背景图**：`backgrounds[tone].dataUrl`（avatarStore.dreamBackgrounds）若设置过灰暗图，经 18px blur + 0.68 透明度就是灰底。确认日间未设图时 `.dream-theme__chat-background` 不渲染（当前疑似空 dataUrl 仍渲染出带 ::after 的空容器，顺手修）。
3. 以上都排除后，直接把日间 `.dream-theme__chat` 的表层提亮：顶层白色渐变从 `0.58/0.38` 提到约 `0.80/0.62`，并确认 `--dt-surface` 未被任何运行时覆写。

无论根因落在哪条，最终按验收标准调出效果，改动集中在 `DreamTokens.css` 日间侧，夜间模式不受影响。

## E. 梦境流动接入（前端半）

现状（已确认是未接入的摆设）：`DreamSidebar.tsx` 读 `dreamState.flow_entries / dream_events / events`，但后端 `GET /dream/state` **从不返回这三个字段**（全仓 grep 无产出点），所以永远走 `buildFallbackFlowEntries` 的三条固定文案。

后端 Brief 25 §2 会正式提供 `flow_entries: [{ts, kind, summary}]`。前端改动：

1. `dream-types.ts`：`flow_entries` 定型为 `{ ts: string; kind: string; summary: string }[]`，删掉 `dream_events`/`events` 两个从未存在的猜测字段。
2. `getBackendFlowEntries`：直接消费 `flow_entries`（保留 `normalizeFlowSummary` 清洗），展示条数从 3 提到 5，最新在上，可带相对时间（复用 SubFlow 的 formatAgo 风格）。
3. fallback 三条固定文案仅在 `flow_entries` 为空时显示（梦刚开始的头几轮），并把 `EVENT_SUMMARY` 死映射删掉。
