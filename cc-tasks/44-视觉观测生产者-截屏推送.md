# 44 · 视觉观测生产者：定时检查/采样 → 变化才 POST /perception/visual

## 背景

后端视觉观测（Brief 56 shadow 模式）只有接收端 `POST /perception/visual` 和只读
trace 面板，**从未有生产者**——本仓 `src-tauri/src/sensor/` 没有任何截屏代码，
所以用户开了开关、填了 GLM key 依然"毫无反应"。契约详情见后端 114-S5 产出的
perception 文档（本单前置：等该文档合入）。

## 设计要点

1. Rust 侧新增 `sensor/visual.rs`：定时（默认 5 分钟，可配）执行后端预检、本地
   开关与锁屏检查后，才在内存中截主屏；以感知哈希比对前一帧，**仅显著变化**时才
   降采样（长边 ≤1280）→ JPEG → POST 后端 `/perception/visual`（走既有 no_proxy
   reqwest 与 token 鉴权）。稳定画面只在内存中比对，绝不周期性上传；图片不落盘。
2. 开关联动：仅当后端 `visual_perception.enabled` 为真且本地用户在设置里
   显式开启"视觉观察"才运行——双闸，默认关。设置项文案走 i18n。
3. 隐私护栏：锁屏/无桌面会话时跳过；失败静默但计数，设置页显示"最近一次
   推送时间/结果"供排障。
4. 平台范围：v1 仅 Windows（截屏 API 平台相关；mac 等 40 号工单落地后再议）。

## 验收

- 双开关开启且画面发生显著变化后，后端 `/perception/visual-trace` 面板出现观测记录；
- 关任一开关即停止推送；锁屏期间无推送；
- `cargo check` + `npx.cmd tsc --noEmit` 通过；`docs/backend-integration.md` 登记。
