# 45 · 群聊/群梦前端锁死修复：409 可见化 + "…"超时兜底

## 背景

用户复现：群梦第二句回复完成后，前端停在"…"待机气泡且输入被锁，无法再发。
后端 round 生命周期已核查干净（`run_dream_stage_turn` 整轮 timeout + finally 释放
+ `_mark_round_finished`，见后端 114-S4）；判定锁死在前端状态机。两个具体缺陷：

1. **409 被静默吞**：`/group/{id}/dream/send` 在 round 未释放/梦境不活跃时返回
   409（"正在回应上一条消息" / "当前没有进行中的梦境"），前端未展示任何反馈，
   用户视角=发不出去且无解释。
2. **"…"与输入闸只等 `group_round_end`**：WS 丢一条 round_end（重连窗口/时序）
   就永久锁死，无超时兜底。

## 改动点

1. 发送失败（含 409/422/网络错误）必须在 UI 给出可见错误提示（i18n 语义 key），
   409 时同时触发一次状态轮询决定是否解锁。
2. "…"气泡与输入闸加超时兜底：超过后端整轮 timeout + 缓冲（从后端拿
   `_DREAM_STAGE_TURN_TIMEOUT_S` 契约值写死+30s 即可）未收到 round_end →
   主动 `GET /group/{id}/dream/state` 用 `round_status`/`last_round_error`
   校准本地状态：idle/failed/timed_out 一律解锁并把 last_round_error 展示出来。
3. WS 重连成功后立即做一次同样的状态校准（防止断线期间错过 round_end）。
4. 群聊（reality stage）侧同样检查是否存在"只等 WS 信号解锁"的对称问题，有则同修。
5. 配合后端 114-S4：沉默轮显式空轮信号落地后，前端对空轮显示轻提示
   （如"（无人接话）"）而不是无限"…"。

## 验收

- 模拟丢失 round_end（断 WS 再重连）→ 超时兜底解锁且状态正确；
- 后端 409 时 UI 有提示且随轮询解锁；
- `npx.cmd tsc --noEmit` + `npm test` 通过；`docs/frontend-structure.md` 群梦章节同步。

## 依赖 / 并行

- 第 5 点依赖后端 114-S4 的空轮信号；其余可立即施工。与 44 并行。
