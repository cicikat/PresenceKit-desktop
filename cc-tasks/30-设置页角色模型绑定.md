# 30 · 设置页：角色 ↔ 模型（routing profile）绑定界面

> 依赖后端 Emerald-presence Brief 87（API 已定义，后端先行）。机制说明：绑定对象是
> **routing profile**（不是裸 preset）——一个 profile 是整套 category→preset 映射，
> 角色卡 `presence_ext.model_routing` 指向它。

## 工单项

1. 🟡 设置页新增「模型绑定」区块：列出全部角色（现有角色列表接口），每行一个下拉框，
   选项 = `GET /model-presets/routing-profiles` 返回的 profile 名 + 「默认」
   （即清除绑定，null）。
2. 🟡 行内展示解析结果：绑定后显示 `GET /character/{id}/model-routing` 返回的
   `resolved_chat_preset`（用户关心的其实是"聊天用哪个模型"，直接给答案，
   不让人脑内解析 profile）。
3. 🟢 校验与反馈：422（profile 不存在，一般是 config 改了）给出明确提示文案；
   保存即生效（后端缓存边沿刷新），无需重启提示。
4. 🟢 群聊说明文案一句：「绑定跟随角色，在单聊与群聊中一致生效」。

## 约定

- 文案全部走 `src/shared/i18n/` 语义 key（协作偏好 7，禁止写死中文）。
- profile 的编辑/新建不做（那是 config 层），界面只做绑定。
- 验收：绑定 → 单聊与群聊该角色实际走对应 preset（配合后端断言）；清除 → 回默认；
  旧后端（无 87 API）→ 区块隐藏降级，不报错。
