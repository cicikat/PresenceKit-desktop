# 21 — 协议权威文档固化(P0,可并行)

## 背景

当前实际协议是 legacy WS + HTTP `/desktop/chat`,双端(本仓 + Emerald-presence)都是 legacy。
v1 目标协议文档躺在旧 `Emerald-desktop` 仓,后端仓没有对应协议文件。没有一份"当前正式协议"的单一权威。

## 决策(已拍板)

**legacy 即 v0.1 正式协议。** 不实现 v1,不做 capabilities 协商,只做文档固化。

## 交付物

新建 `docs/protocol-v0.md`,作为客户端↔后端协议的单一权威,内容:

1. **WS 消息全集**(从 `src/shared/api/ws.ts` + `types.ts` 逆向,以代码为准):
   `hello`/`hello_ack`、`channel_message`、`message_segments`、`action`、`ack`、
   `ping`/`pong`、`message_stream_start/delta/end`、`group_round_start/end`。
   每条列字段、方向、ack 要求。
2. **Action allowlist 冻结**(9 类,以 `ws.ts _dispatchAction` 为准):
   `minimize_window`、`open_url`、`show_notify`、`media_play_pause`、`play_netease`、
   `dream_invite`、`toy_invite`、`presence_nag`、`avatar_directive`。
   写明:未知 action → `ack ok:false + error` 的 nack 语义;`action_type`/`type` 双字段兼容;
   参数从 `params` 优先读取。v0.1 不新增 action 类型。
3. **HTTP 发送 + WS 回复双路径声明**:`/desktop/chat` 是 v0.1 正式发送路径(不是过渡态),
   回复可能从 HTTP 响应或 WS 到达,去重契约见 `docs/chat-correlation.md`(工单 22 产出,先留链接)。
4. **v1 roadmap 附录**:把 `backend-integration.md` 的 v1 目标表格移进来,标注"未排期,双端未实现"。

改 `docs/backend-integration.md`:协议部分收缩为指向 `protocol-v0.md` 的链接,删除重复叙述。

## 验收

- 协议文档与 `ws.ts`/`types.ts` 逐条核对无出入。
- `backend-integration.md` 不再有与 protocol-v0.md 冲突的协议描述。
- 建议同步在 Emerald-presence 仓 docs/ 放一份指针文件(仅链接,不复制内容)——另开后端仓工单。

## 依赖

无。可与所有工单并行。工单 22、25 引用本文档产出。
